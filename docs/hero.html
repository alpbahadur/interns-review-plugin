Claude Code plugin

Your agent's first idea is a draft.
interns-review makes it a decision.

Every proposed design or bug fix gets torn apart by 1–3 independent Fable reviewers before it reaches you. The lead agent verifies their findings against the code, keeps what's real, and ships the rest.

1

Agent proposes

Problem, pointers, constraints, and the proposed fix go into one context file.

# consensus-ctx.md ## Problem Auth tokens accepted 1 tick after expiry ## Pointers auth/mw.ts:42 ## Proposed change `<` to `<=` ## Doubt only check site?
›
2

Reviewers attack

Parallel Fable subagents. Each gets a different lens. None sees the others.

Correctness & root causefable
Edge cases & blast radiusfable
Simplicity & over-engineeringfable
›
3

Lead filters

Findings are treated as intern findings. Verified against code. Wrong ones die.

✔ ACCEPT mw.ts:42 off-by-one verified in code ✔ ACCEPT missing test for boundary tick ✘ REJECT "add token cache layer" — over-engineered ✘ REJECT mw.ts:118 claim not in code (unverified)
›
4

Final solution

Accepted findings folded in. Short receipt of what changed and why.
